# TasteSift MVP 1.1

Dennis approved this scope in voice after reviewing the five-item checklist. Continue inline in the existing project and feature branch; do not repeat the approval gate.

## Approved behavior

1. Show continuous animated feedback and actual import stages. Read structured post recipes directly when available; otherwise transcribe and organize with the existing Mac tools. Never fabricate a percentage. Saving still requires explicit confirmation.
2. Load current cuisine and dish-type options before extraction and editing. Prefer existing categories, use dropdowns, and create a new category only after explicit confirmation. Chinese and English labels identify the same category. Existing recipes and their values must remain usable.
3. Upload or replace a cover from the recipe editor, preview it, and save its reference with the recipe. Validate file content and size server-side. Store uploaded files privately in the Site's R2 bucket. Supply the missing potato example cover from its original public video.
4. Switch the complete recipe interface between Chinese and English; preserve unsaved form values during switching. Interface translation does not translate the source recipe text. Remember the language in a browser cookie.
5. Remove MVP badges, test copy and fixed example links from normal use. Put examples and version information on an owner-only internal test page. Keep real instructions, errors, attribution and import limitations visible.

## Architecture and decisions

Reuse Vinext/React, Sites identity, D1, existing recipe services and the neighboring Video Knowledge Extraction code. Use newline-delimited progress events over the existing local helper request, with JSON fallback for compatibility. Mac-only importing remains the selected architecture; phones can view and save hosted results.

Use a catalog with bilingual labels and normalized unique aliases. Add only schema migrations, with no rewriting of existing recipes. Merge the initial familiar cuisines/dish types and existing saved values into the catalog. Both recipe-write and API boundaries validate against current options.

Use the existing `BUCKET` binding for uploads. Accept JPEG, PNG and WebP up to 5 MiB, checking their signatures and bounded request bodies. Serve uploaded images only to authenticated members. Uploading may precede recipe confirmation; do not auto-delete files that could be referenced by another draft.

Keep the existing one-folder/native workflow, private Site audience and role permissions. No family-management expansion, paid AI setup, automatic source-content translation, public sharing or remote Mac tunnels.
